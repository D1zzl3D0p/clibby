# Four new body-family motion studies

These are original, working **experimental motion and model implementations**,
not selectable resident pets. They deliberately exercise the families that the
current production biped/quadruped controllers cannot represent. No changes to
Qt, production manifests, the catalogue selector or existing pets are made here.

| Pet | Implemented here | Still outside this study |
| --- | --- | --- |
| Pebblekin | Flat stationary stone footprint; upper stone pivots and bounded wobble/recovery | Live interaction, drag/drop and host support changes |
| Margin | Corresponding 32-vertex ink contour; continuous comma and exclamation morphs within a fixed envelope | Resident deforming mesh adapter and interaction |
| Lantern Snail | Translating continuous sole with 50 boundary samples on the floor; upper-body curve, retract/peek, eye stalks and hinged shell door | Host movement realization, slope/support changes and drag/drop |
| Velvet | Six articulated legs; alternating world-pinned tripods; root stays inside the planted support hull; decorative wing reveal | Host realization, turn/recovery, antenna grooming and flight |

The user selected refined, simple pixel-rendered 3D art with a recognizable
silhouette. These models use that medium and a common orthographic 96×96 render
grid. They remain first art studies; the precise contours, wing pattern and ink
character should be reviewed in motion before production asset work. There are
no externally sourced models, textures, downloaded assets or AI-generated images.

## Source and evaluation contract

`motion.py` has no Blender or Qt dependency. `evaluate(pet, seconds)` returns an
immutable pose without changing state. Coordinates are world authoring units,
Z up. A finite demonstration starts after one second, ends by six seconds and
then holds exactly, even for very large elapsed times. Quiet evaluations do not
request ticks. This is a pure demonstration sampler, **not** the production
intent → propose → host realize transaction or resident deadline scheduler.

`contacts` describes actual discrete feet only. Pebblekin and the snail have no
invented legs: their `support_polygon` describes the anchored base or continuous
sole. Velvet's six named contacts distinguish planted and swinging feet; at
least three remain planted, with no world-space sliding in stance. Its knee
positions are authored procedural bends, not a production two-link IK solver.
Margin's support field is a bounded-body envelope, not a physical floor solver.

`render.py` contains editable original low-poly model recipes. Blender builds
the actual 3D geometry from evaluated poses. Each generated `source.blend` saves
the first pose for editing; procedural motion is regenerated by the source
recipe, rather than stored as a baked animation. `make_previews.py` quantizes
the actual renders without dithering, thresholds transparency, and enlarges
with nearest filtering. Each pet has 7–11 available colours.

## Reproduce

From the repository root, with the installed Blender and project virtualenv:

```sh
rtk proxy /Applications/Blender.app/Contents/MacOS/Blender --background --python experiments/catalogue-families/render.py -- --frames 120
rtk proxy .venv/bin/python experiments/catalogue-families/make_previews.py
rtk proxy .venv/bin/python -m unittest discover -s tests -p test_catalogue_families.py
```

Blender needs ordinary host execution on this Mac because graphics-library
initialization fails inside the restricted execution sandbox. CPU Cycles uses
four samples; this is offline authoring, not a resident performance measurement.
Use `--frames 1` only for a fast still; the preview assembler requires 120 frames.

Generated files live in ignored
`results/catalogue-families-2026-10-16/`: the four editable `.blend` files, raw
and palette-bound frames, recorded support/contact poses, individual motion
GIFs, `families-motion.gif`, `families-rest.png`, `contact-sheet.png`, palette
statistics and render statistics. Every study contains 120 source frames at
15 fps, eight seconds including quiet rest at both ends. The root moves in the
snail and moth demonstrations; the GIFs intentionally loop back to the initial
location after the final quiet hold.

## Verification and next boundary

Twelve behavioral tests exercise immutable deterministic reads, finite settling,
invalid input rejection, supported capabilities, anchored support, continuous
crawl support, bounded visible morphs, planted tripod count, exact world pins,
root containment inside the planted support hull, and the actual stone meshes'
contact throughout the upper-stone rocking motion. The renderer and test consume
the same original faceted mesh geometry: the lowest upper-stone vertex stays on
the middle stone's actual flat support face, within its boundary. The narrow
contact patch is visible at 96px; a geometric apex alone can disappear between
pixels. The focused post-correction suite passes all 12 checks; the complete
Python suite passes 72 checks. Actual-size light/dark and
enlarged rest/action frames have been inspected.

These results do not establish resident scheduling, pickup/drop, desktop
interaction, production package compatibility, flight, energy use or platform
parity. Promoting a new family requires its own validated native controller,
host support and suppression integration; the experimental capabilities must
not be advertised by the production catalogue before those exist.
