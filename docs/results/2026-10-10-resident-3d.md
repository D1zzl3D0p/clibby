# Live werewolf on the desktop

The original skinned werewolf is now a selectable character in `better_pets`.
The existing resident owns its tray, controls, preferences, sessions, notification
cards and scheduler. The 3D preview remains available.

## Implementation

- `SpatialCharacter` owns a timerless scene binding and trusted QML engine.
  A distinct `builtin-3d` descriptor dispatches the werewolf without treating it
  as a 2D character definition. Failed preparation retains the live character.
- The motion core now separates reset, bounded proposal and actual realization.
  Host feedback preserves contacts across integer placement, edge clamping and
  drag/display rebasing. Preview `step()` retains its prior convenience behavior.
- A 384×384 logical transparent stage uses a 128×128 nearest GPU composition.
  The horizontal projection is calibrated at 120 logical pixels per meter.
  The user's follow-up adds a −35° facing bias and a 12° top-down
  camera tilt for a three-quarter, semi-isometric look. Camera pitch preserves
  horizontal travel. Resident headings mirror to −35° right and −145° left,
  keeping the torso toward the camera over a shorter 110° reversal. A bounded
  rotational impulse and stronger damped yaw spring accelerate the body turn;
  planted stance limits still constrain the torso while paws replant one at a time.
  Model world travel is removed from local drawing, so the following window does
  not apply movement twice. Vertical support stays inside the surface.
- Projected joint/limb envelopes supply conservative visual masks; a separate
  torso grab region controls dragging. Head/card anchors use the same projection.
  These masks do not promise pixel-perfect click-through.
- Shared controls drive walking, stopping, speed and suppression. Session-owned
  reaction progress drives nod/look/success/failure. Pause, hidden and settled
  states freeze live texture updates; changed poses request one final update.
  Unchanged ambient ticks do not rewrite 3D joints or masks.
- Selection restores identity, speed, pause and exact saved window placement.
  Callback guards prevent old-scene anchor access during swaps. A native 3D
  rendering error hides the pet while retaining tray controls and sessions.
- Converted mesh, texture, rig and trusted stage resources deploy beside the
  executable in `better-pets-3d`. Blender/Balsam are build dependencies only.
  A build with `BETTER_PETS_WITH_3D=OFF` remains usable.

## Camera-facing turn refinement

The user requested an impulse to hold the desired three-quarter body turn and
avoid showing the werewolf's back during leftward travel. Resident motion now
opts into mirrored camera-facing headings; the preview retains its prior mode.
Yaw uses a 7 Hz critically damped spring with a one-shot velocity impulse capped
at 3 rad/s. Torso yaw stays within the planted stance and camera-facing interval,
with angular displacement limited to 4.7 rad/s. Unchanged destinations do not
repeat the impulse. Foot timing and the 0.4 rad lifted-paw yaw budget stay intact.

At 600 Hz simulation and 2× speed, the old additive 180° reversal reached 90%
of heading change in 2.94 s; the new 110° reversal took 1.803 s. With mirrored
headings alone and the old spring/no impulse, it took 1.847 s. The spring and
impulse primarily improve initial response; safe paw replants govern completion.

## Remaining acceptance

Manual click-through/fringe assessment, gesture cropping at all native scales,
multi-monitor crossing and actual sleep/wake need desktop review. The native
Spaces placement failures remain open. Matched 2D/3D process/GPU/WindowServer
measurements and controlled energy testing are still required. Autonomous
wandering, arbitrary downloaded 3D models and object-aware interactions are
outside this integration slice.

## Try it

Select `Character → werewolf-3d`, or launch:

```sh
rtk proxy build/qt/better_pets --character "$PWD/characters/werewolf-3d"
```

Use the menu-bar icon or right-click for walking, stopping, Pause/Resume,
Show/Hide and Toolbox. Preserve `better-pets-3d` beside the executable if moving
the built application. The descriptor selects only the trusted built-in asset;
it does not load package-provided QML or shaders.
